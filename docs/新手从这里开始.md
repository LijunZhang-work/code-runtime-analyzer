# 新手从这里开始

如果你以前没用过这个工具，就按这篇做。先不要看“整体方案”“技术边界”等文档。

## 先明白它在做什么

普通日志分析的麻烦是：代码在编辑器里，历史数据在 CSV 里。你需要自己猜“这一列数据对应哪段代码”。

这个工具通过一份**字段字典**把两边连起来。连接成功后，你可以选择一个历史时间点，直接在代码旁查看当时的值。

## 先安装（只做一次）

1. 到 [GitHub Releases](https://github.com/LijunZhang-work/code-runtime-analyzer/releases/latest) 下载同一版本的 EXE 和“默认右侧栏版”VSIX；需要 OpenCode 时再下载 MCP 包；
2. 双击 EXE，只安装后台和 Web；
3. 从 Windows 开始菜单打开“Code Runtime Analyzer → 后台控制中心”，确认后台正在运行；
4. 在你实际使用的标准或公司定制版编辑器中，单独选择“从 VSIX 安装”；
5. 编辑器明确提示安装成功后，重新加载一次编辑器窗口。

正常情况下直接下载 Release，不需要 Node.js 或 npm。如果默认右侧栏版被编辑器拒绝安装，或者重新加载后仍找不到“历史诊断”，先卸载默认版，再改用同一版本的“兼容布局版”VSIX，两个版本不要同时安装。兼容布局版的扩展自身功能相同，入口可能在左侧；代码定位、类型和调用关系到底能用多少，以自动兼容性检测为准。如果公司网络下载 Release 很慢，可以下载源码 ZIP，再按 [从源码生成安装包](从源码生成安装包.md) 运行一条构建命令；不要直接把源码 ZIP 当成安装包。EXE 不会自动碰任何编辑器，VSIX 是否安装成功由你实际使用的编辑器明确显示。

## 你需要准备什么

准备下面三样东西：

1. 一个 C/C++ 代码仓；
2. 一份适合这个产品的字段字典；
3. 一个装有本次日志 CSV 的文件夹。

如果你还没有字典，先看 [字段字典填写指南](字段字典填写说明.md)。仓库里的 `backend/dictionaries/2048-demo.csv` 可以作为例子。

## 第一次打开工具

1. 用你实际使用的编辑器打开 C/C++ 代码仓根目录，不要只打开某一个 `.cpp` 文件；
2. 找到“历史诊断”；默认版在右侧，兼容布局版可能在左侧活动栏；
3. 如果没有这个面板，确认已经安装并启用了 Code Runtime Analyzer 扩展；
4. 打开一个你想查看的 `.c`、`.cc`、`.cpp` 或头文件。

面板最上方会自动出现“编辑器兼容性”。它不是只看编辑器叫什么，而是真的尝试查询代码定义、类型、引用和函数调用关系。先看“可以使用 / 部分可用 / 等待检测 / 暂不可用”这句短结论；不明白时点击“查看详细解释”，后面会逐项告诉你“这是什么意思、检查到了什么、现在怎么做”。

## 第一次加载数据

在“历史诊断”面板依次操作：

1. 点“选择字段字典”，选择当前产品；
2. 点“选择 CSV 文件夹”，选择本次导出日志所在的文件夹；
3. 点“加载 / 重新加载字典”；
4. 点“加载 / 重新加载 CSV”；
5. 点“选择回放时间”，选择一个时间点；
6. 点“开始展示”。

成功后，当前屏幕中能看见的 C/C++ 文件会出现历史值。鼠标放到对应代码上，还可以看到数据来源等信息。

## 为什么我点了却没显示

按下面顺序检查：

1. 是否已经点了“开始展示”；
2. 当前打开的是否是 C/C++ 文件，并查看“编辑器兼容性”是否已经完成；
3. 字典中的 CSV 文件名和真实文件名是否完全一样，包括大小写；
4. 字典中的列名和 CSV 第一行是否完全一样；
5. 字典中的定义文件路径是否能从代码仓根目录找到；
6. 兼容性详细解释中的“查定义”和“类型证据”是否可用。

本阶段在编辑器在线时直接使用编辑器已有的语言能力，不要求你为了本工具另做 `compile_commands.json`，也不要求安装某个写死名称的 C/C++ 扩展。没有足够证据时，工具会隐藏该条历史值，不会猜一个看似正确但实际错误的结果。

如果“历史诊断”面板出现红色错误，不要只看“失败”两个字。错误中通常会写明是哪份字典、第几行、缺哪个文件或列。

## 什么时候需要重新加载

- 换了一批 CSV：点“加载 / 重新加载 CSV”；
- 修改了字典：点“加载 / 重新加载字典”；
- 只是换了历史时间：直接重新选择时间，不需要重新解析代码；
- 暂时不想看历史值：点“结束展示”。

“结束展示”只会把代码旁的值隐藏，不会删除你的字典和 CSV。
