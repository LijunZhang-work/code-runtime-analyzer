# 第一阶段实施计划

## 目标

完成可验证的“产品字典—多 CSV 文件夹—C++ 字段—历史时间点—VS Code 证据展示”闭环，以数据正确性和 fail-closed 为优先级。

## 0.4.0 实施顺序

1. **字典契约**：后台内置多套五列 CSV 字典；产品 A/B 分别维护自己的字典，不使用 manifest 或 run config。
2. **运行文件夹导入**：右侧面板选择字典和一个含多份标准 CSV 的文件夹；按 `data_source` 精确加载全部必需来源。
3. **时间与映射**：每源恰好一行 `time`；`member` 以 `QualifiedType::field` 为身份并支持 `{index}`，`symbol` 使用完整限定名。
4. **路径与代码分析**：校验仓库相对 `definition_path`；自动发现唯一编译数据库和候选函数，再由 Clang 产生语义事实。
5. **VS Code 证据**：选择时间，展示行尾摘要、Hover、CodeLens、完整趋势、数据质量和明确的无数据/歧义状态。
6. **真实样例验收**：使用真实产品字典、源码和多 CSV 故障文件夹验证端到端结果。

所有关键选择遵循 0/1/>1：0 个候选明确缺失，1 个候选采用，多于 1 个候选停止并请求消歧，禁止静默选择第一个。

## 当前完成定义

第 1 至第 5 项已在 0.4.0 形成可运行链路。2048 演示通过内置 `2048-demo` 字典一次加载两个 CSV，展开 35 个映射实例；用户不维护实验 JSON 或机器相关编译路径。

第 6 项仍未完成。2048 只证明受控诊断夹具能够闭环，正式收口仍需用户真实业务样本、UI 自动化、大文件性能和复杂构建上下文验证。

## 外部前置条件

- 目标 C/C++ 代码仓根目录；
- 能生成或已有可被自动发现的 `compile_commands.json`；
- 一套对应产品的后台字典；
- 一个包含字典所需全部 CSV 的故障运行文件夹；
- 一个可复现的故障时间点或短窗口。
