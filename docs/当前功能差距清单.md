# 当前功能差距清单

本文以 0.5.0 的接入方式为准。旧的 run config、manifest、实验场 `field-mappings.csv` 和手工维护 `compile_commands.json` 路径不再属于用户流程。

## 0.5.0 已完成

- 后台内置扫描 `backend/dictionaries/*.csv`，一个文件就是一套产品字典，无 manifest JSON。
- VS Code 右侧 **历史诊断** 面板可先选字典，再选择一个包含多份 CSV 的运行文件夹。
- 字典固定五列：`data_source,data_field,target_kind,target,definition_path`。
- `target_kind` 收敛为 `time/member/symbol`；`member` 同时支持精确列名和单个 `{index}` 模式。
- `data_source` 按第一层标准 CSV 精确文件名匹配并严格区分大小写；标准 CSV 不存在 sheet 概念。
- 一个字典可要求多份 CSV；缺少任意必需文件时整次加载 fail closed，额外 CSV 只报告为未使用。
- `definition_path` 使用代码仓根目录相对 POSIX 路径，并检查绝对路径、`.`/`..`、反斜杠、真实大小写、文件存在及符号链接越界。
- 每个来源恰好一行 `time`；字典和数据 CSV 支持 UTF-8 BOM，非法 UTF-8 会直接报错而不是显示乱码。
- 成员映射身份使用完整 owner 类型与字段名，不依赖 module 或局部 variablePath；独立全局量使用完整限定符号名。
- 自动发现当前代码仓中的 `compile_commands.json` 和候选函数，并由 Clang 最终验证；用户不维护 replay JSON 或机器相关 build 绝对路径。
- 同一源文件在编译数据库中出现多套不同命令时报告编译上下文歧义并停止，不再静默取第一条；同时支持标准 `arguments` 条目。
- 2048 字典同时加载 `2048_demo_run.csv` 和 `2048_metrics.csv`，展开 35 个映射实例和 8 个时间点。
- 安装版 VSIX 自带 0.5 后端；每个 VS Code 窗口使用动态端口和独立 Worker，无需用户手工运行 Node。
- 行尾快照、丰富 Hover、CodeLens、完整趋势、基础 CSV 数据质量、无数据提示和状态恢复已经形成闭环。
- Clang 索引改为持久化 clangd：每个文件只冷解析一次，支持自由函数和成员函数；后台全仓索引关闭，队列并发为一，缓存有数量和内存上限。
- 切换时间点复用代码结构、使用一个批量快照请求；不再重新运行 Clang，也不再在普通刷新中拉取全部趋势。
- CSV 最近时间查询改为二分，百万点统计改为单趟；旧请求 generation、未保存文件和保存失效已做 fail-closed 处理。

## P0：第一阶段正式收口前

- 使用一套用户真实业务源码、真实产品字典和多 CSV 故障文件夹完成端到端验收；2048 仍是受控夹具。
- 为右侧面板的字典选择、文件夹选择、0/1/>1 错误路径、时间选择、刷新、趋势和恢复增加完整 UI 自动化测试。
- 验证多个真实构建目录、不同 target/config 与重复 compile command 下的 fail-closed 交互。
- 为头文件建立严格的 TU 反向关系；0 个上下文报告缺失，多个非等价上下文要求选择，不能采用 clangd 猜测的第一个命令。
- 在字典加载或首次选定构建上下文时，用 Clang 验证 `Type::field`/全局符号确实存在且唯一，而不只验证定义文件存在。

## 已知语义边界

行尾内容表示所选时间点的 CSV 字段快照，不等同于程序执行到该源码行时捕获的局部变量。`current.value`、`target.value` 等引用可由 Clang 确认属于某个 owner 类型，但没有动态 Trace 时不能确定当次对应哪个数组下标，只能展示相应成员的全实例快照。
