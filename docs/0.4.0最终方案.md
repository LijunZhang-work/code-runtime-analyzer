# 0.4.0 最终方案

> 阅读对象：工具研发和维护人员。第一次使用工具不需要看这篇，请先看 [新手从这里开始](新手从这里开始.md)。这篇只记录 0.4.0 的历史设计，不代表当前架构和操作步骤。当前版本已经改为“独立后台核心 + VS Code / 网页 / OpenCode 多客户端”，请看 [整体方案总览](整体方案总览.md)。

0.4.0 把字段字典从代码仓移到诊断后台。后台可以内置多套字典；用户在 VS Code 右侧“历史诊断”面板中选择字典，再一次选择一个包含多个 CSV 的文件夹。

## 用户操作

1. 用 VS Code 打开要分析的代码仓。
2. 在右侧面板选择产品字典，例如 `ProductA` 或 `ProductB`。
3. 选择本次运行产生的 CSV 文件夹。
4. 后台严格检查文件名、表头、时间列和代码定义。
5. 选择时间点，在源码行尾、Hover 和趋势面板中查看数据。

产品 A 和产品 B 即使位于同一个代码仓，也分别使用自己的字典。选择不同字典就是选择不同产品的字段含义，不需要在每一行重复填写产品名称。

## 后台字典

后台扫描 `backend/dictionaries` 中的 CSV 文件。一个 CSV 文件就是一套可选择的字典，不再配套 `manifest.json`。

字典固定五列：

```csv
data_source,data_field,target_kind,target,definition_path
```

- `data_source`：所选数据文件夹中的精确文件名。严格区分大小写。
- `data_field`：CSV 表头中的精确字段名；数组宽表可以使用一个 `{index}` 模式。
- `target_kind`：第一阶段只支持 `time`、`member`、`symbol`。
- `target`：`time` 填时间格式；`member` 填完整的 `类型::字段`；`symbol` 填完整代码符号。
- `definition_path`：代码目标定义文件相对于当前 VS Code 代码仓根目录的路径，统一使用 `/`。

示例：

```csv
data_source,data_field,target_kind,target,definition_path
Students.csv,timestamp,time,unix_ms,
Students.csv,name,member,school::Student::name,include/model/Student.hpp
Students.csv,age,member,school::Student::age,include/model/Student.hpp
Runtime.csv,timestamp,time,unix_ms,
Runtime.csv,error_code,symbol,telemetry::g_error_code,src/telemetry.cpp
```

`time` 行让同一个字典同时说明每份 CSV 的时间列和时间格式，因此不再需要用户维护 `replay-run-config.json`。

## 两种路径基准

- 数据文件以用户在右侧面板选择的 CSV 文件夹为基准。例如字典中的 `Students.csv` 会在所选文件夹下查找。
- 代码定义以 VS Code 当前打开的代码仓根目录为基准。例如 `include/model/Student.hpp` 会在当前工作区下解析。

字典不保存任何电脑上的绝对路径，所以同一套后台和字典复制到不同电脑后仍可使用。

## 严格匹配

- 普通 CSV 没有 Sheet；第一阶段按文件夹中的多个 CSV 加载。
- 文件名和字段名大小写必须完全一致，不做相似名猜测。
- 缺少字典要求的 CSV、重复表头、非法编码或无时间列时停止加载并明确报错。
- 文件夹中额外的 CSV 不参与映射，但在右侧面板列为“未使用文件”。
- `definition_path` 不能是绝对路径，不能包含 `.`、`..` 或反斜杠，也不能越出代码仓。
- Clang 负责解析指针、引用、`const`、`typedef`、`using`、命名空间和字段真实声明者。
- 找到零个代码目标时报“未找到”；找到多个时报“有歧义”；只有唯一目标才接受，绝不自动选择第一个。

字典确认的是类型字段，例如 `school::Student::age`。代码中的变量可以叫 `stu`、`left`、`right` 或是指针；变量名不参与语义匹配。没有运行时对象标识时，界面只表示“这里访问了该类型字段”，不谎称 CSV 值属于某一个具体对象。

## 编译信息

用户不再填写字典清单 JSON 或运行配置 JSON。构建工具生成的 `compile_commands.json` 由扩展自动查找并交给后台使用，因为 Clang 需要它还原实际的头文件目录、宏和编译参数；它不属于人工字典，也不需要用户修改。

如果工作区只找到一份就直接使用；如果找到多份，就提示用户选择一次并只把选择记在当前工作区状态中，不新建项目 JSON 文件。

安装版扩展会自动启动随 VSIX 打包的 0.4 后台；端口上已有兼容后台时直接复用。若端口被旧版后台占用，会明确提示关闭旧版，不再出现一闪而过却不知道原因的窗口。
