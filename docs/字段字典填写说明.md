# 字段字典填写指南

## 先用一句大白话说明

字段字典就是一张“翻译表”：它告诉工具，某个 CSV 文件中的某一列，代表代码里的哪一个字段或全局符号。

一个产品写一份字典。例如产品 A 使用 `product-a.csv`，产品 B 使用 `product-b.csv`。同一代码仓可以放多份产品字典，用户在右侧面板选择本次使用哪一份。字典不写电脑盘符，所以同一仓库换到另一台电脑后不用改。

字典文件放在：

```text
backend/dictionaries/
```

## 固定的五列

第一行必须原样写成：

```csv
data_source,data_field,target_kind,target,definition_path
```

| 列名 | 大白话解释 | 例子 |
| --- | --- | --- |
| `data_source` | 数据来自哪一份 CSV。必须写完整文件名，大小写也要相同。 | `student.csv` |
| `data_field` | CSV 第一行中的列名。真实 CSV 写 `age`，这里就写 `age`。 | `age` |
| `target_kind` | 这行数据在代码里是什么：时间、类型成员或独立符号。 | `time`、`member`、`symbol` |
| `target` | 它在 C/C++ 中的完整身份。 | `school::Student::age` |
| `definition_path` | 它真正定义在哪个文件；写相对代码仓根目录的路径。 | `src/student.hpp` |

不要增加 `cpp_type`、`cpp_global` 等新列。结构体字段、全局变量和以后其他种类都通过 `target_kind` 区分，因此列数一直固定。

## 最常见的结构体字段

假设真实 CSV 是：

```csv
timestamp,name,age
1710000000000,Alice,18
```

C++ 代码是：

```cpp
namespace school {
struct Student {
  std::string name;
  int age;
};
}
```

字典写：

```csv
data_source,data_field,target_kind,target,definition_path
student.csv,timestamp,time,unix_ms,
student.csv,name,member,school::Student::name,src/student.hpp
student.csv,age,member,school::Student::age,src/student.hpp
```

关键点：CSV 里就是 `age`，不用改成 `student_age`。工具根据 `school::Student::age` 知道它属于哪个类型。

代码里变量可以叫 `stu`、`left`、`right`，也可以是指针；变量名会变，但类型和成员名不变，所以字典不写局部变量名。

如果另一产品的 CSV 也有一列 `age`，就在另一份产品字典中把它映射到那个产品自己的类型。不同 CSV 文件里可以出现同名列；同一份 CSV 的表头不能出现两个完全相同的 `age`，否则无法唯一取值。

## 全局变量或其他独立符号

```csv
runtime.csv,timestamp,time,iso8601,
runtime.csv,frame_count,symbol,telemetry::g_frame_count,src/telemetry.hpp
```

这里 `frame_count` 是 CSV 列名，`telemetry::g_frame_count` 是代码中的完整符号名。

## 三种 target_kind 怎么选

- `time`：时间列。每份数据 CSV 必须恰好一行。`target` 只能写 `unix_ms` 或 `iso8601`，`definition_path` 留空。
- `member`：类、结构体或联合体的成员。`target` 写完整的 `命名空间::类型::字段`。
- `symbol`：不依附某个对象的独立程序符号，例如全局变量。`target` 写完整限定名。

如果将来支持新种类，只增加新的 `target_kind` 值，不改变这五列。

## definition_path 怎么写

路径的起点是用户当前打开的代码仓根目录。例如代码仓是：

```text
my-product/
  src/student.hpp
```

就写 `src/student.hpp`，不要写 `C:\Users\...` 或 `E:\...`。

还要遵守：

- 只使用 `/`；
- 大小写与仓库中的真实文件一致；
- 指向真正声明字段或符号的文件，不是随便一个使用它的 `.cpp`；
- 不使用 `.`、`..`，也不能指向代码仓外面。

这列能区分“名字相同，但在不同文件里各自定义”的情况。不同电脑克隆同一仓库时，相对路径仍然有效。

## 文件名、Sheet 和文件夹

标准 CSV 是单表文本文件，没有 Excel Sheet。因此 `data_source` 只写严格匹配的文件名，例如 `Metrics.csv`；`Metrics.csv` 与 `metrics.csv` 会被视为不同文件。

如果原始数据来自 Excel，请先把每个需要分析的 Sheet 分别导出成 CSV，再按导出后的精确文件名填写。工具一次选择一个文件夹，可以从这个文件夹第一层加载多份 CSV，但不会递归扫描子目录。

## 数组列

如果 CSV 表头是 `TILE_0_VALUE`、`TILE_1_VALUE`，可以写：

```csv
board.csv,TILE_{index}_VALUE,member,Game::tile_t::value,src/tile.hpp
```

`{index}` 必须恰好出现一次。工具会按真实表头展开，找不到或匹配不唯一就报错，不会猜。

## 写完后怎么自查

1. 文件保存为 UTF-8 CSV；
2. 表头五列名称和顺序完全正确；
3. 每份数据 CSV 恰好有一行 `time`；
4. 文件名和列名与真实 CSV 大小写完全一致；
5. `member` 写完整类型和字段名，不写局部变量名；
6. `definition_path` 能从代码仓根目录找到真实定义文件；
7. 在右侧面板选择字典和 CSV 文件夹，点击“加载 / 重新加载”，根据错误中的字典行号修正。

可运行示例见 `backend/dictionaries/2048-demo.csv`。
