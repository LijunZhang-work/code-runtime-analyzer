# 字段字典填写指南

这篇说明写给第一次制作字典的人。先照着例子做，不需要先了解后端代码。

## 一、字典到底是什么

CSV 只知道自己有一列叫 `age`，但它不知道这列在 C++ 中属于 `Student`、`Teacher`，还是某个全局变量。

字典就是人工写的一张翻译表，明确告诉工具：

> 哪一份 CSV 的哪一列，对应代码中的哪一个东西，以及这个东西定义在哪个文件。

一个产品使用一份字典。同一代码仓有产品 A、产品 B 时，就写两份字典，由用户在右侧面板选择。

## 二、字典文件放在哪里

把字典 CSV 放进：

```text
backend/dictionaries/
```

文件名尽量直接表达产品，例如：

```text
product-a.csv
product-b.csv
energy-controller.csv
```

不要使用某台电脑的用户名或盘符作为字典名。

## 三、先复制这个最小模板

新建 UTF-8 格式的 CSV，先粘贴：

```csv
data_source,data_field,target_kind,target,definition_path
你的数据.csv,你的时间列,time,unix_ms,
你的数据.csv,你的数据列,member,命名空间::类型::字段,定义文件的相对路径
```

第一行五个英文列名不能改名、不能换顺序，也不要自己增加列。

## 四、五列分别填什么

### 第 1 列：data_source

填写真实数据文件的完整名字，包括 `.csv`。

例如真实文件叫：

```text
StudentLog.csv
```

就必须写 `StudentLog.csv`。不能写 `studentlog.csv`，也不能只写 `StudentLog`。

### 第 2 列：data_field

填写真实 CSV 第一行中的列名。

如果真实 CSV 是：

```csv
timestamp,name,age
```

这里就写 `timestamp`、`name` 或 `age`。真实数据里叫 `age`，字典里也写 `age`，不需要改成 `student_age`。

### 第 3 列：target_kind

告诉工具代码目标属于哪一类：

| 填写值 | 什么时候用 |
| --- | --- |
| `time` | CSV 的时间列 |
| `member` | 类、结构体或联合体的字段 |
| `symbol` | 全局变量等独立程序符号 |

结构体和全局变量共用同一套五列，不会因为以后增加新种类就不断增加新列。

### 第 4 列：target

填写它在代码里的完整身份。

结构体字段示例：

```text
school::Student::age
```

全局变量示例：

```text
telemetry::g_frame_count
```

不要写局部变量名。代码里可以有 `Student stu`、`Student left`、`Student* current`，这些变量名会变；字典关心的是稳定的类型和字段 `Student::age`。

时间行的 `target` 只写：

- `unix_ms`：例如 `1710000000000`；
- `iso8601`：例如 `2026-08-03T10:30:00Z`。

### 第 5 列：definition_path

填写字段或符号真正定义在哪个代码文件中，路径从代码仓根目录开始。

例如仓库结构是：

```text
my-product/
  src/
    student.hpp
```

就写：

```text
src/student.hpp
```

不要写 `C:\Users\...`、`E:\...` 等绝对路径。这样同一代码仓换一台电脑也不用修改字典。

时间行没有代码定义，因此这一列留空。

## 五、完整的结构体例子

真实 CSV `student.csv`：

```csv
timestamp,name,age
1710000000000,Alice,18
1710000001000,Alice,19
```

C++：

```cpp
namespace school {
struct Student {
  std::string name;
  int age;
};
}
```

字典：

```csv
data_source,data_field,target_kind,target,definition_path
student.csv,timestamp,time,unix_ms,
student.csv,name,member,school::Student::name,src/student.hpp
student.csv,age,member,school::Student::age,src/student.hpp
```

## 六、完整的全局变量例子

真实 CSV 有一列 `frame_count`，代码中对应全局符号 `telemetry::g_frame_count`：

```csv
data_source,data_field,target_kind,target,definition_path
runtime.csv,timestamp,time,iso8601,
runtime.csv,frame_count,symbol,telemetry::g_frame_count,src/telemetry.hpp
```

## 七、同名字段怎么办

不同产品的 CSV 都可以有 `age`，因为它们使用不同字典。

同一份 CSV 的表头不能同时出现两个完全相同的 `age`，否则工具无法知道应该读取哪一列，会直接报错而不是猜一个。

如果代码中不同地方定义了同名类型或字段，使用 `definition_path` 指明真正的定义文件。

## 八、一份文件里的 Sheet 怎么办

标准 CSV 是一个纯文本表，没有 Excel Sheet。

如果你的原始文件是 Excel，并且里面有多个 Sheet，请先把需要的 Sheet 分别导出成不同 CSV，例如：

```text
Students.csv
Teachers.csv
```

然后在 `data_source` 中分别填写精确文件名。一次选择的文件夹可以放多份 CSV。

## 九、数组列怎么写

如果 CSV 第一行中有：

```text
TILE_0_VALUE,TILE_1_VALUE,TILE_2_VALUE
```

可以写：

```csv
board.csv,TILE_{index}_VALUE,member,Game::tile_t::value,src/tile.hpp
```

`{index}` 必须恰好出现一次。工具会按真实表头展开为 0、1、2。第一次写字典时如果没有数组列，可以先跳过这一节。

## 十、写完后的检查清单

逐项确认：

1. 文件是 UTF-8 CSV；
2. 第一行五列完全正确；
3. 每份数据 CSV 恰好有一行 `time`；
4. `data_source` 与真实文件名完全一致；
5. `data_field` 与真实 CSV 表头完全一致；
6. `member` 写的是完整类型和字段，不是局部变量名；
7. `definition_path` 从代码仓根目录能够找到真实文件；
8. 路径使用 `/`，没有盘符、`.` 或 `..`；
9. 在右侧面板重新加载字典和 CSV，根据报错中的行号修正。

可以直接参考仓库中的 `backend/dictionaries/2048-demo.csv` 和 `runs/` 下的两份虚构演示 CSV。
