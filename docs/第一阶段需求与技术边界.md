# 第一阶段：代码行级历史值回放

## 1. 阶段目标

第一阶段只建立一个可在真实问题中稳定运行的最小闭环：开发人员在 VS Code 中打开指定 C/C++ 函数，选择一组 CSV 运行日志与一个故障时间点后，能够直接看到该函数相关字段的历史值、数据来源和短期变化。

本阶段的目标是减少人工在代码与多个 CSV 之间重复搜索，而不是重建真实执行路径或自动判定根因。

## 2. 验收场景

选择一个真实故障样本，满足以下条件：

- 有可编译或可分析的 C/C++ 项目；
- 构建系统已生成可由后台自动发现的 `compile_commands.json`；0 个或多个不同候选时必须明确提示，不能猜测；
- 有一组 CSV 日志，且至少一个 CSV 含时间列；
- 用户能够指定相关模块、文件或入口函数；
- 目标函数内存在结构体字段访问，最好包含结构体数组和普通 `for` 循环；
- 后台中存在对应产品的五列字段字典，且字段能通过 `time/member/symbol` 规则唯一对应到 CSV 列。

验收时，开发人员应能完成：

1. 打开目标函数并选择一次运行记录；
2. 选择故障时间点或短时间窗口；
3. 在相关代码行旁看到字段历史值；
4. 识别简单结构体数组循环中的匹配索引或实例摘要；
5. 在 Hover 中看到字段当前值、前后变化、CSV 文件和列名；
6. 点击字段打开完整的短期趋势或时间序列视图；
7. 明确知道每个值是精确命中、最近采样、聚合、插值还是无数据；
8. 不再需要手工逐个搜索多个 CSV 来完成上述过程。

## 3. 用户与主要流程

### 3.1 目标用户

直接用户是排查测试故障的 C/C++ 开发人员；间接用户是测试人员、模块负责人和诊断辅助 AI。

### 3.2 主流程

1. 用户用 VS Code 打开代码仓，并在右侧面板选择对应产品字典。
2. 用户一次选择包含本次运行多份标准 CSV 的文件夹。
3. 后端按字典中的 `data_source` 和 `time` 行完成文件、表头、时间与定义路径校验。
4. 用户选择故障时间点或窗口，进入“历史回放模式”。
5. 扩展根据当前文件、函数和代码位置请求相关字段的数据。
6. 扩展显示精简的行内摘要；Hover 展示详细证据和趋势。
7. 用户从字段入口查看时间序列、同一结构体实例及 CSV 来源。

## 4. 功能范围

### 4.1 输入

| 输入 | 要求 |
|---|---|
| C/C++ 项目 | 指定根目录与分析范围 |
| 编译信息 | 后台自动发现 `compile_commands.json`；0/1/>1 候选必须 fail closed |
| CSV 运行记录 | 用户选择一个文件夹，一个运行记录可含多个标准 CSV 文件 |
| 时间规则 | 每个 `data_source` 在字典中恰好一行 `time` |
| 字段映射配置 | 后台内置对应产品的固定五列 CSV 字典 |
| 回放选择 | 单一时间点或时间窗口 |

### 4.2 代码分析能力

第一阶段需要识别并索引：

- 函数定义、文件位置和函数范围；
- 结构体与字段定义；
- 函数体中的字段访问；
- 简单字段读写（赋值左侧可视为写入，其余为读取，无法确定时标注）；
- 固定数组下标，例如 `items[2].id`；
- 普通 `for` 循环中的整数索引，例如 `items[i].id`；
- 条件表达式中涉及的字段；
- 简单直接函数调用（为后续阶段预留索引）。

暂不保证解析：复杂宏展开、函数指针、虚函数分派、复杂模板、跨函数别名、跨线程写入、动态容器及复杂指针链。

### 4.3 CSV 导入与时间查询

后端需要支持多个 CSV 的独立解析和统一查询。每条返回数据必须包含：

- 值与原始文本；
- CSV 文件标识和列名；
- 实际采样时间；
- 用户请求时间；
- 匹配类型；
- 请求时间与采样时间的差值；
- 映射规则与置信度。

支持的匹配类型定义如下：

| 类型 | 定义 | 界面要求 |
|---|---|---|
| 精确命中 | 采样时间与请求时间相同 | 直接显示“精确” |
| 最近采样 | 在允许容差内选择最近一条记录 | 显示实际采样时间及偏差 |
| 区间聚合 | 对窗口内数据按配置聚合 | 显示聚合方式和窗口 |
| 插值 | 根据相邻样本估算 | 明示“插值”，不可伪装为记录值 |
| 无数据 | 不存在可用值或超出容差 | 显示无数据和原因 |

### 4.4 字段映射

后台扫描 `backend/dictionaries/*.csv`。一个文件就是一套产品字典；产品 A、产品 B 使用不同文件，不需要 manifest 或运行配置 JSON。固定表头为：

```csv
data_source,data_field,target_kind,target,definition_path
```

`target_kind` 只支持：`time`、`member`、`symbol`。`member.target` 始终是完整的 `QualifiedType::field`；`data_field` 可以是精确 CSV 列名，也可以恰含一个 `{index}` 模式。

数组字段映射需要支持将 CSV 列中出现的实例编号映射回代码索引，例如：

```text
BOSS_2_BOSS_ID  ->  bossInfo[2].bossId
BOSS_2_STATUS   ->  bossInfo[2].status
```

`data_source` 是所选文件夹第一层的精确 CSV 文件名，严格区分大小写；标准 CSV 没有 sheet。`definition_path` 是仓库根相对 POSIX 路径，成员必须指向真实定义文件，`time` 行留空。

文件、数据列、编译配置与代码目标均采用 0/1/>1：0 个明确缺失，1 个采用，多于 1 个报告歧义并停止。额外 CSV 只报告为未使用，不参与导入。

### 4.5 VS Code 交互

**时间选择。** 用户可选择运行记录、单一时间点或时间窗口；当前选择需在扩展范围内保持一致。

**行内摘要。** 仅对当前函数中已映射且与当前行相关的字段显示信息，避免遮挡代码。例如：

```text
i=2 | bossId=17 | targetId=17 | 条件：true
```

值的显示必须带有必要状态标识，例如 `17（最近采样，-20 ms）`。无法可靠计算条件结果时，只显示字段值并说明限制。

**Hover。** 悬浮字段时显示当前值、CSV 来源、匹配类型、采样偏差、前后 N 个采样点或 N 秒的变化、最小值、最大值、变化次数，以及同一数组实例中已映射的相关字段。

**字段详情。** 点击或右键“查看历史趋势”，打开完整时间序列视图；首版可采用 VS Code Webview 或简单的本地网页。

**CodeLens。** 函数上方显示已映射字段数量、存在数据的字段数量和故障窗口内发生变化的字段数量。例如：`关联 8 个字段 | 6 个有数据 | 2 个在窗口内变化`。

## 5. 最小数据模型

以下模型可以作为 API 和持久化设计的共同语言：

```text
Dictionary
  id, dataSources[], fixedColumns(data_source,data_field,target_kind,target,definition_path)

RunRecord
  id, dictionaryId, selectedFolder, csvFiles[], unusedFiles[]

CsvSource
  id, runRecordId, path, timeColumn, timeFormat, timezone, schema

CodeFieldIdentity
  targetKind(member|symbol), qualifiedType, fieldName, qualifiedSymbol,
  index, definitionPath, sourceLocation

FieldMapping
  codeFieldIdentity, dataSourceFileName, csvColumn, indexRule

TimeQuery
  runRecordId, requestedTime, mode(exact|nearest|aggregate|interpolate), tolerance

EvidenceValue
  mappingId, value, rawValue, requestedTime, sampledTime,
  matchType, offset, csvSourceId, csvColumn, confidence
```

## 6. 接口边界

第一阶段可以采用本地 HTTP、JSON-RPC 或标准输入输出协议，但接口需稳定并支持后续 Web/AI 复用。最小接口包括：

- 创建/查询项目索引；
- 导入、列出和校验运行记录；
- 查询 CSV 架构、时间范围和时间质量；
- 创建、确认、查询字段映射；
- 查询函数中的字段访问；
- 按时间点或窗口查询字段证据；
- 查询某字段的时间序列和同实例字段。

扩展只消费这些接口，不直接实现 CSV 扫描或复杂静态分析。

## 7. 明确不纳入本阶段

- 重放真实函数调用顺序或证明某条分支实际执行；
- 全项目完整调用图与回调精确解析；
- 自动根因判断；
- 功能块自动划分；
- 复杂指针别名、宏展开和多线程因果关系；
- 将全量代码、全量 CSV 发送给 AI；
- 动态 Trace 采集、特殊版本编译和烧录流程。

## 8. 质量与风险控制

### 8.1 时间数据

导入时检查时间解析失败、非单调时间、重复时间、采样间隔异常、缺失区间和不同 CSV 的覆盖范围。用户应能看到对齐策略和容差配置。

### 8.2 映射可信度

同名字段、多个候选列和未知单位必须降低置信度。未经确认的候选映射可供用户查看，但不得默认作为可靠诊断证据。

### 8.3 性能

CSV 原始数据可能很大。第一阶段应避免每次 Hover 全量扫描文件：导入时建立列元数据与时间索引，趋势图按需要读取目标列和窗口；界面查询采用当前函数与当前时间范围的局部数据。

### 8.4 可解释性

任何行内值和趋势详情至少显示：代码字段身份、CSV 来源、列名、采样时间、匹配类型和映射来源。无数据、未映射和低置信度是正常结果，应明确显示。

## 9. 阶段交付物

1. 本地分析后端的最小可运行服务；
2. 项目代码索引与字段访问结果；
3. CSV 导入、时间质量校验和时间查询能力；
4. 字段映射规则与人工确认持久化；
5. VS Code 扩展的时间选择、行内摘要、Hover、字段详情与 CodeLens；
6. 一个真实故障样本的端到端演示数据、配置和验收记录；
7. 已知限制清单，明确所有降级或不确定结果的展示方式。

## 10. 阶段退出标准

只有当验收样本可重复地完成以下闭环，第一阶段才可视为完成：用户从目标函数进入，选择故障时间，在相关代码行看到与 CSV 正确映射的历史值；对于结构体数组能查看合理的实例信息；Hover 能展示趋势和来源；每个结果的时间匹配与映射可信度明确可见；过程无需用户手工在多份 CSV 中检索字段。
