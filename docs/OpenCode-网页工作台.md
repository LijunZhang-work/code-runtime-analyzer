# OpenCode、AI 与网页工作台

这篇写给想让 OpenCode 或其他 AI 查询代码和历史运行数据的人。普通用户不需要安装 Node.js，也不需要执行 npm。

## 一句话说明

安装 `Code-Runtime-Analyzer-Setup-v*.exe` 后，电脑上会有一套独立运行的“代码运行分析后台”。编辑器扩展和 MCP 都需要用户另外安装；连接后，它们与网页共用同一套字典、CSV、代码分析结果和缓存。

```text
编辑器扩展   ─┐
网页工作台   ─┼─→ Code Runtime Analyzer 后台
OpenCode/AI ─┘       ├─ 产品字典
                     ├─ 本次 CSV
                     ├─ C/C++ 代码分析
                     └─ 以后增加的模块级能力
```

后台不是只为某一个编辑器扩展服务的小附件，它才是产品核心。以后接入新的编辑器、网页能力或 AI 工具，不需要复制一套字典、CSV 和业务逻辑。

## 普通用户怎样使用

1. 从 GitHub Releases 下载并运行 `Code-Runtime-Analyzer-Setup-v*.exe`。
2. 安装完成后打开实际使用的编辑器，在“历史诊断”面板加载产品字典和本次 CSV 文件夹。
3. 点击“打开网页工作台”。从哪个编辑器窗口打开，网页就与哪个窗口绑定。
4. 网页里的“在当前编辑器中定位”会回到这个窗口，不会另开一个窗口。
5. 想接 OpenCode 时，先按 [MCP 手动安装说明](MCP手动安装.md) 安装同版本 MCP 包，再进入网页左侧“AI 与扩展”复制配置。

EXE 只包含后台、网页和后台运行环境，不安装编辑器扩展或 MCP，也不修改 OpenCode、WSL 和任何编辑器配置。

## OpenCode 怎样连接

MCP 安装完成后，网页“AI 与扩展”页面提供两份配置：

- “新版 OpenCode”：使用 `mcp.servers` 格式；
- “OpenCode 1.x”：保留旧版 `mcp` 格式。

复制后放到当前代码仓自己的 OpenCode 配置中。不同 OpenCode 版本的配置位置可能不同，以 OpenCode 自己显示的配置文件位置为准。

单独安装的 MCP 程序不会启动第二套后台。它只连接已经安装并正在运行的本机后台。`47831` 只是首选端口；被其他程序占用时后台会自动换端口，所以不要自己把地址写死。

如果 MCP 直接运行在 Windows，它会读取当前用户的后台连接记录。如果 OpenCode 运行在 WSL，请从当前后台打开的网页“AI 与扩展”页面复制配置；该配置已经包含这一次真实使用的地址和随机访问密钥。后台重新启动后密钥会变化，需要重新复制配置，旧配置不会再被接受。

这个地址只监听本机，局域网或互联网中的其他电脑不能直接访问。

如果 OpenCode 运行在 WSL 中，就在 WSL 中安装 MCP 包。安装和配置可以交给该环境里的 AI，但必须以 OpenCode 显示已连接、后台显示 AI 客户端在线为准。

## 如何确认真的连上了

1. 打开网页工作台的“AI 与扩展”。
2. “后台核心”应显示已连接和版本号。
3. OpenCode 启动 MCP 后，“OpenCode / AI 客户端”中应出现一个在线客户端。
4. 编辑器窗口打开时，“编辑器窗口”中应显示对应窗口。

这个页面显示的是后台真实记录到的连接，不是装饰性的假状态。

## OpenCode 可以做什么

OpenCode 可以让 AI 调用这些真实能力：

| 能力 | 大白话说明 |
| --- | --- |
| 列出产品字典 | 看后台有哪些产品可选 |
| 加载数据 | 选择一套字典和本次 CSV 文件夹 |
| 列出时间点 | 看日志里有哪些可回放时刻 |
| 查询快照 | 查询某个时间点的字段值 |
| 查询趋势 | 查询一个字段随时间怎样变化 |
| 查询调用关系 | 当前编辑器窗口在线时，由网页通过窗口专属通道查询；旧离线接口不是当前推荐流程 |

例如可以按这个顺序问：

1. “列出可以使用的产品字典。”
2. “使用 ProductA 字典，加载这个 CSV 文件夹。”
3. “列出可查询的时间点。”
4. “查询 `school::Student::age` 在这个时间点的值和来源。”
5. “显示这个字段最近一段时间的变化趋势。”

## 为什么网页要从编辑器打开

后台会给每个编辑器窗口建立一个临时会话。网页地址带着这个会话编号，所以网页知道应该把语义查询和定位请求发给哪一个窗口。

如果直接从浏览器收藏夹打开普通网页，仍然能浏览数据，但没有来源窗口时，网页无法查询该窗口的函数关系，也无法判断定位应该回到哪里。此时从目标编辑器窗口重新打开网页即可。

## 维护者从源码运行

只有开发和修改本工具时才需要根目录的 npm 命令。源码模式与安装版使用相同接口，但维护者应避免同时启动两个占用同一端口的后台。
