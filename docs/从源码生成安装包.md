# 从源码生成 EXE、VSIX 和 MCP 包

这篇说明适合 GitHub Release 下载很慢、但下载源码很快的电脑。你可以让本机 AI 按这篇执行，也可以自己复制一条命令。

## 最简单的方法

1. 在 GitHub 下载源码 ZIP 并解压；
2. 安装 Node.js 20 或更高版本；
3. 在源码根目录打开 PowerShell；
4. 执行：

```powershell
.\build.ps1 all
```

构建完成后，所有文件都在根目录的 `dist` 文件夹中。

第一次生成 EXE 时，脚本会自动下载并校验一份固定版本的免安装 NSIS，放在项目自己的 `tools/nsis` 目录，不修改系统安装。以后再次生成时会直接复用。只生成扩展或 MCP 时不会下载 NSIS。

如果不熟悉 PowerShell，也可以双击 `build.cmd`。它默认生成全部文件，并在窗口关闭前保留错误信息。

## 只生成其中一种

```powershell
# 只生成 Windows 后台安装程序
.\build.ps1 exe

# 只生成编辑器扩展（一次生成两个二选一的 VSIX）
.\build.ps1 extension

# 只生成 OpenCode / AI MCP 安装包
.\build.ps1 mcp
```

也可以使用：

```text
build.cmd exe
build.cmd extension
build.cmd mcp
```

## 最后会得到什么

```text
dist/
├─ Code-Runtime-Analyzer-Setup-v版本号.exe
├─ Code-Runtime-Analyzer-默认右侧栏-v版本号.vsix
├─ Code-Runtime-Analyzer-兼容布局-v版本号.vsix
├─ Code-Runtime-Analyzer-MCP-v版本号.tgz
└─ SHA256SUMS.txt
```

- EXE：只安装后台控制中心、分析后台和 Web，不安装扩展或 MCP；
- 默认右侧栏 VSIX：优先安装，面板使用编辑器右侧栏；
- 兼容布局 VSIX：默认版被拒绝安装，或重新加载后仍找不到“历史诊断”时再用；扩展自身功能相同，入口可能在左侧活动栏，实际代码能力以自动检测为准；两个 VSIX 只安装一个；
- MCP：由用户或 AI 安装到 OpenCode 所在环境；
- SHA256SUMS：用来确认文件没有损坏或被替换。

## 脚本会自动做什么

脚本会自动安装锁定的项目依赖、准备 EXE 打包工具、构建 Web、编译扩展、准备后台文件、生成安装包并计算校验值。用户不需要记忆内部 npm 命令。

如果失败，脚本会停在真实失败步骤，并说明是缺少 Node.js、NSIS 免安装包下载或校验失败，还是某项代码没有通过构建。不要忽略错误后继续使用残缺文件。

## 给本机 AI 的一句话

可以直接告诉本机 AI：

> 请在本仓库根目录运行 `.\build.ps1 all`。如果缺少 Node.js 20，请安装后重新运行；NSIS 由脚本自动准备。不要修改产品代码和用户数据。
