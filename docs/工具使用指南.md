# 工具使用指南

## 这个工具解决什么问题

你在看 C/C++ 代码时，可以选择一批带时间点的 CSV 日志。工具会把某个时间点的历史值显示到对应代码旁边，还能查看趋势、数据质量和当前函数的直接调用关系。

## 第一次安装

开发环境需要：

- VS Code；
- Node.js 20 或更高版本；
- clangd；
- CMake（C/C++ 工程需要生成 `compile_commands.json`）。

克隆仓库后，在仓库根目录执行：

```powershell
npm run install:all
npm test
```

开发扩展时，在 VS Code 中按 F5 会打开扩展开发窗口。正式使用时应安装发布的 VSIX，不需要每次按 F5，也不需要手工启动后台；扩展会在当前 VS Code 窗口内启动自己的本地后台。

## 日常使用：按这个顺序点

打开 VS Code 右侧的“历史诊断”面板：

1. **选择字段字典**：选择当前产品；
2. **选择 CSV 文件夹**：选择本次导出的日志目录，一次只能使用一个目录，但目录里可以有多份 CSV；
3. **加载 / 重新加载字典**：明确采用磁盘上的这份字典；
4. **加载 / 重新加载 CSV**：清除旧数据缓存，重新读取当前目录；
5. **选择回放时间**：选择你要看的时间点；
6. **开始展示**：只分析当前屏幕上看得见的 C/C++ 文件，并显示行末值、悬停信息等；
7. **结束展示**：立即隐藏所有历史值并释放分析内存，但不会删除字典或 CSV 文件。

关闭并重新打开 VS Code 后，工具默认不显示上一次的数据。只有用户再次加载并开始展示，数据才会出现，避免把旧日志误当成当前结果。

## 缓存不会怎样“串数据”

- 重新加载字典或 CSV 时，旧数据版本和旧分析结果全部失效；
- 已经发出的旧请求即使晚回来，也不能覆盖新数据；
- 修改代码只重新分析代码，不删除字典和 CSV；
- 当前可见的分屏文件一直保留展示；不可见标签页可以释放重型缓存，再次查看时重新解析；
- 工具不会偷偷监听并换用磁盘上的新 CSV。是否重新加载由用户点击按钮决定。

## 网页工作台

把光标放进一个 C/C++ 函数，在右侧面板点击“打开网页工作台”。网页会展示当前函数在当前编译单元中能够确认的直接调用关系。

点击网页中的“在当前 VS Code 中定位”，会回到发起打开网页的那个 VS Code 窗口。为保证大型项目可读和不卡顿，网页不会一次画完整代码仓；跨文件、虚函数、回调和函数指针等无法静态确认的关系会明确提示，不会伪造连线。

## OpenCode

仓库根目录已经提供 `opencode.json`。在这台电脑上，OpenCode 位于 WSL，而 Node.js 位于 Windows，因此配置使用 `node.exe` 启动 MCP。

从 WSL 进入本仓库后检查：

```bash
cd /mnt/<盘符>/<你的克隆目录>
opencode mcp list
```

看到 `cpp-csv-diagnostics connected` 就表示连接成功。之后可以让 OpenCode：

- “列出可用的产品字典”；
- “用 product-a 字典加载这个 CSV 文件夹”；
- “列出这次日志可用的时间点”；
- “查询某个字段在这个时间点的值和来源”；
- “分析当前 C++ 文件中这个函数的直接调用链”。

如果另一台电脑是在 Linux/macOS 原生运行 OpenCode，把 `opencode.json` 中的 `node.exe` 改成 `node`；Windows 或 WSL 调 Windows Node 时保持 `node.exe`。

## 常见问题

- **健康检查失败**：先确认 Node.js 20+ 可用，再重新加载窗口；正式安装的扩展不需要手工运行后台。
- **字典加载失败**：根据报错中的文件名和行号检查五列表头、大小写、列名和定义路径。
- **代码旁没有值**：确认已经加载字典和 CSV、选择时间并点击“开始展示”，且当前文件是已保存的 C/C++ 文件。
- **找不到调用关系**：确认工程已生成 `compile_commands.json`，当前文件使用的编译配置正确，并把光标放在有直接调用的函数体内。
- **修改了 CSV 但页面没变化**：点击“加载 / 重新加载 CSV”。工具不会擅自监听并替换当前分析数据。
