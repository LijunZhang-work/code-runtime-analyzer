# 工具使用指南

这篇说明写给第一次使用工具的人。你只需要会打开 VS Code、选择文件和文件夹。

## 一、先安装 VS Code 扩展（普通用户不需要 npm）

你只需要安装一次。请不要点 GitHub 页面上的绿色 `Code` 按钮，也不要下载 `Download ZIP`；那是给开发者看的源码，不是安装包。

1. 打开 [GitHub Releases（正式安装包）](https://github.com/LijunZhang-work/code-runtime-analyzer/releases/latest)；
2. 下载名称以 `.vsix` 结尾的文件，例如 `Code-Runtime-Analyzer-v0.9.2.vsix`；
3. 打开 VS Code，点击左侧“扩展”；
4. 点击扩展面板右上角的 `...`；
5. 选择“从 VSIX 安装”；
6. 选择刚下载的 `.vsix` 文件；
7. 按 VS Code 的提示重新加载窗口。

安装完成后，扩展、内置后台和网页工作台都会一起装好。**不需要安装 Node.js、不需要打开终端、不需要运行 npm。**

只有修改本项目源码、制作下一版安装包的维护者，才需要使用 npm 命令；这与普通使用无关。

> 说明：安装包不会替你安装 C/C++ 编译器。分析代码位置时，扩展会使用这个代码仓本来就该有的 `compile_commands.json` 和 clangd；缺少时右侧面板会明确提示，不会要求你去运行 npm。

## 二、工具界面在哪里

用 VS Code 打开你的 C/C++ 代码仓后，在窗口**右侧**找到“历史诊断”面板。

如果没有看到：

1. 点击 VS Code 左侧“扩展”；
2. 确认 Code Runtime Analyzer 扩展已经安装并启用；
3. 执行“开发人员：重新加载窗口”；
4. 仍然没有时，确认你打开的是代码仓文件夹，而不是只打开一个文件。

## 三、正式使用前准备什么

### 1. 代码仓

就是你的 C/C++ 项目根目录。字典里的相对路径都从这里开始计算。

### 2. 字段字典

字典告诉工具“CSV 列对应代码中的什么”。它通常由熟悉产品代码的人提前写好，保存在工具的 `backend/dictionaries/` 目录。

不会写字典时请看 [字段字典填写指南](字段字典填写说明.md)。

### 3. CSV 文件夹

这是本次要分析的日志文件夹。一次选择一个文件夹，但里面可以有多份 CSV。

这个文件夹是临时分析数据，不是字典。下次分析另一批日志时，可以换成另一个文件夹。

## 四、右侧按钮按什么顺序点

### 第 1 步：选择字段字典

点击“选择字段字典”，选择当前产品对应的字典。

例如你分析产品 A，就选择产品 A 的字典。不要因为两份字典里都有 `age` 或 `status` 就随便选；不同产品可能把同名列映射到完全不同的代码类型。

### 第 2 步：选择 CSV 文件夹

点击“选择 CSV 文件夹”，选择这一次日志所在的文件夹。

工具只读取这个文件夹第一层的 CSV，不会自动进入子文件夹。

### 第 3 步：加载字典和 CSV

依次点击：

1. “加载 / 重新加载字典”；
2. “加载 / 重新加载 CSV”。

这是在明确告诉工具：“我要使用磁盘上现在这份内容。”工具不会偷偷监视文件变化，也不会在你不知情时换数据。

### 第 4 步：选择回放时间

点击“选择回放时间”，从 CSV 中已有的时间点里选择一个。

如果没有时间点，通常说明 CSV 没有成功加载，或者字典中的时间列写错了。

### 第 5 步：开始展示

点击“开始展示”。

工具只分析当前屏幕中真正看得见的 C/C++ 编辑器。如果你左右分屏看两个文件，这两个文件都会保留展示；其他没有显示在屏幕上的标签页不占用长期重型缓存。

### 第 6 步：结束展示

点击“结束展示”后，代码行末、鼠标悬停信息和趋势窗口都会停止展示。

它不会删除：

- 字段字典文件；
- CSV 文件；
- 你的代码；
- 右侧面板中已经选择过的路径。

## 五、什么时候点“重新加载”

| 发生了什么 | 应该怎么做 |
| --- | --- |
| 换了另一个 CSV 文件夹 | 选择新文件夹，再点“加载 / 重新加载 CSV” |
| 覆盖或修改了当前 CSV | 点“加载 / 重新加载 CSV” |
| 修改了字典内容 | 点“加载 / 重新加载字典” |
| 只是换时间点 | 重新选择时间即可 |
| 修改了 C/C++ 代码 | 保存文件，工具重新分析当前可见文件 |
| 暂时不想看数据 | 点“结束展示” |

重新加载字典或 CSV 时，旧缓存会失效，避免上一批日志混进这一批。

## 六、鼠标悬停和趋势怎么看

历史值显示后，把鼠标放到对应字段或代码位置上，可以看到：

- 当前时间点的值；
- 数据来自哪份 CSV、哪一列；
- 字典映射到哪个代码字段；
- 是否精确命中时间，还是取了允许范围内的最近时间。

需要查看一段时间内的变化时，打开字段趋势。趋势只是读取 CSV，不会重新解析整个 C/C++ 项目。

## 七、网页函数调用关系

1. 打开一个已保存的 C/C++ 文件；
2. 把光标放在某个函数体内；
3. 在右侧面板点击“打开网页工作台”。

网页会显示当前函数能够静态确认的直接调用关系。点击“在当前 VS Code 中定位”，会回到打开这个网页的同一个 VS Code 窗口。

为了大型项目不卡顿，网页不会一次加载整个代码仓。虚函数、回调和函数指针如果无法静态确认，也不会被画成假的确定关系。

## 八、常见错误怎么处理

### “健康检查没有通过”

扩展内置后台没有正常启动。先重新加载 VS Code 窗口；如果仍失败，确认安装包中包含 `backend/`，开发打包前要运行 `npm run prepare:extension`。

### “找不到 CSV”

检查字典里的 `data_source`。文件名、大小写和 `.csv` 后缀都必须与真实文件一致。

### “找不到列”

打开真实 CSV，看第一行表头。字典里的 `data_field` 必须与它完全一致，不能自己改成更好看的名字。

### “定义路径不存在”

字典中的 `definition_path` 是相对代码仓根目录的路径。不要写某台电脑的 `C:\...` 或 `E:\...` 绝对路径。

### “网页没有调用连线”

确认光标在有调用行为的函数内，并确认工程已经生成 `compile_commands.json`。有些函数确实没有直接调用其他函数，这时显示单个节点是正常的。

## 九、OpenCode 怎么用

普通用户不使用 OpenCode 也不影响 VS Code 功能。需要 AI 查询时，再看 [OpenCode 使用说明](OpenCode-网页工作台.md)。
