# 工具使用指南

这篇说明写给第一次使用工具的人。你只需要会打开编辑器、选择文件和文件夹。

## 一、安装后台和扩展（普通用户不需要 npm）

最省事的方法是下载 GitHub Release 里的现成安装包。只有公司网络下载 Release 很慢时，才下载源码 ZIP，并按照 [从源码生成安装包](从源码生成安装包.md) 执行一条构建命令；不要把源码 ZIP 本身当成安装包。

1. 打开 [GitHub Releases（正式安装包）](https://github.com/LijunZhang-work/code-runtime-analyzer/releases/latest)；
2. 下载同一版本的 `Code-Runtime-Analyzer-Setup-v*.exe`；扩展先下载 `Code-Runtime-Analyzer-默认右侧栏-v*.vsix`，需要 OpenCode 时再下载 `Code-Runtime-Analyzer-MCP-v*.tgz`；
3. 双击 EXE，只安装独立后台和 Web 工作台；
4. 在 Windows 开始菜单打开 `Code Runtime Analyzer → 后台控制中心`，确认显示“后台状态：正在运行”；
5. 在你实际使用的编辑器中选择“从 VSIX 安装”，选中刚下载的 `.vsix`；公司定制版编辑器也应在它自己的扩展管理界面中安装；如果默认右侧栏版被拒绝安装，或者重新加载窗口后仍找不到“历史诊断”，先卸载默认版，再安装 `Code-Runtime-Analyzer-兼容布局-v*.vsix`，二者不要同时安装；
6. 只有编辑器明确显示“安装成功”，才算扩展安装完成。已经打开的编辑器按提示重新加载一次窗口。

EXE 不会自动安装、卸载或修改任何编辑器，所以不会再出现“猜错编辑器路径却静默失败”。**不需要安装 Node.js、不需要打开终端、不需要运行 npm。** 安装时如果勾选“登录 Windows 后自动启动后台”，以后登录时后台会静默启动，不会弹出黑色命令窗口。

后台、Web、扩展和 MCP 是相互分开的部分：后台负责真正的分析和数据；Web 是后台提供的网页界面；扩展和 MCP 都是用户单独安装的连接器。只弹出 Web 不代表扩展或 MCP 已经安装。

后台平时静默运行，但不是“找不到”：开始菜单的“后台控制中心”可以查看状态、启动、停止、重启、打开 Web 和打开日志。

只有修改本项目源码、制作下一版安装包的维护者，才需要使用 npm 命令；这与普通使用无关。

> 说明：本阶段只处理“代码仓已经在编辑器中打开”的情况。扩展会直接询问当前编辑器已经提供的 C/C++ 语义能力，不要求你为本工具单独生成 `compile_commands.json`，也不要求必须安装某个指定名称的 C/C++ 扩展。公司自带的语言能力只要能回答这些标准请求，也可以使用。

## 二、工具界面在哪里

用编辑器打开你的 C/C++ 代码仓后，先找“历史诊断”面板。

- 默认右侧栏版：入口应在编辑器右侧栏；
- 兼容布局版：为了兼容较老或经过定制的编辑器，入口可能出现在左侧活动栏；
- 无论入口在哪，点击“编辑器兼容性 → 查看详细解释”，报告都会单独打开在代码右边，不需要你凭肉眼猜安装是否成功。

如果没有看到：

1. 点击编辑器的“扩展”入口；
2. 确认 Code Runtime Analyzer 扩展已经安装并启用；
3. 执行“开发人员：重新加载窗口”；
4. 仍然没有时，确认你打开的是代码仓文件夹，而不是只打开一个文件。

首次安装后，请先打开一个 C/C++ 文件。面板最上方会自动显示“编辑器兼容性”的简短结论：

- **可以使用**：关键能力已经实测通过；
- **部分可用**：历史值或调用关系中的一部分可用，点开详细解释会告诉你缺什么、会影响什么、现在怎么做；
- **等待检测**：通常是还没打开 C/C++ 文件，或语言服务仍在索引；
- **暂不可用**：报告会保留具体失败原因和可复制的诊断信息。

检测不会只看编辑器名字、扩展名字或版本号。它会实际发出“查定义、查类型、查引用、查调用关系”等请求，再按照真实响应给结论。你也可以点击“重新检测编辑器兼容性”。

## 三、正式使用前准备什么

### 1. 代码仓

就是你的 C/C++ 项目根目录。字典里的相对路径都从这里开始计算。

### 2. 字段字典

字典告诉工具“CSV 列对应代码中的什么”。它通常由熟悉产品代码的人提前写好，保存在工具的 `backend/dictionaries/` 目录。

不会写字典时请看 [字段字典填写指南](字段字典填写说明.md)。

### 3. CSV 文件夹

这是本次要分析的日志文件夹。一次选择一个文件夹，但里面可以有多份 CSV。

这个文件夹是临时分析数据，不是字典。下次分析另一批日志时，可以换成另一个文件夹。

## 四、“历史诊断”按钮按什么顺序点

### 第 1 步：选择字段字典

点击“选择字段字典”，选择当前产品对应的字典。

例如你分析产品 A，就选择产品 A 的字典。不要因为两份字典里都有 `age` 或 `status` 就随便选；不同产品可能把同名列映射到完全不同的代码类型。

### 第 2 步：选择 CSV 文件夹

点击“选择 CSV 文件夹”，选择这一次日志所在的文件夹。

工具只读取这个文件夹第一层的 CSV，不会自动进入子文件夹。

### 第 3 步：加载字典和 CSV

依次点击：

1. “加载 / 重新加载字典”；
2. “加载 / 重新加载 CSV”。

这是在明确告诉工具：“我要使用磁盘上现在这份内容。”工具不会偷偷监视文件变化，也不会在你不知情时换数据。

### 第 4 步：选择回放时间

点击“选择回放时间”，从 CSV 中已有的时间点里选择一个。

如果没有时间点，通常说明 CSV 没有成功加载，或者字典中的时间列写错了。

### 第 5 步：开始展示

点击“开始展示”。

工具只分析当前屏幕中真正看得见的 C/C++ 编辑器。如果你左右分屏看两个文件，这两个文件都会保留展示；其他没有显示在屏幕上的标签页不占用长期重型缓存。

### 第 6 步：结束展示

点击“结束展示”后，代码行末、鼠标悬停信息和趋势窗口都会停止展示。

它不会删除：

- 字段字典文件；
- CSV 文件；
- 你的代码；
- “历史诊断”面板中已经选择过的路径。

## 五、什么时候点“重新加载”

| 发生了什么 | 应该怎么做 |
| --- | --- |
| 换了另一个 CSV 文件夹 | 选择新文件夹，再点“加载 / 重新加载 CSV” |
| 覆盖或修改了当前 CSV | 点“加载 / 重新加载 CSV” |
| 修改了字典内容 | 点“加载 / 重新加载字典” |
| 只是换时间点 | 重新选择时间即可 |
| 修改了 C/C++ 代码 | 工具会清掉当前文件的旧结果，并按编辑器当前内容重新确认；不必为了本工具强制保存 |
| 暂时不想看数据 | 点“结束展示” |

重新加载字典或 CSV 时，旧缓存会失效，避免上一批日志混进这一批。

## 六、鼠标悬停和趋势怎么看

历史值显示后，把鼠标放到对应字段或代码位置上，可以看到：

- 当前时间点的值；
- 数据来自哪份 CSV、哪一列；
- 字典映射到哪个代码字段；
- 是否精确命中时间，还是取了允许范围内的最近时间。

需要查看一段时间内的变化时，打开字段趋势。趋势只是读取 CSV，不会重新解析整个 C/C++ 项目。

## 七、网页函数调用关系

1. 打开一个 C/C++ 文件；
2. 把光标放在某个函数体内；
3. 在“历史诊断”面板点击“打开网页工作台”。

网页会向打开它的那一个编辑器窗口请求当前函数能够确认的直接调用关系。点击“在当前编辑器中定位”，也只会回到原来的窗口，不使用容易打开错窗口的系统级链接。

为了大型项目不卡顿，网页不会一次加载整个代码仓。虚函数、回调和函数指针如果无法静态确认，也不会被画成假的确定关系。

## 八、常见错误怎么处理

### “无法连接独立后台”或“健康检查没有通过”

先从 Windows 开始菜单打开 `Code Runtime Analyzer → 后台控制中心`。如果显示“未运行”，选择“启动后台”；如果启动失败，选择“打开后台日志”。不要反复重装扩展来掩盖后台问题。

### VSIX 安装后没有看到扩展

确认编辑器明确显示了安装成功。先用默认右侧栏版；如果编辑器提示版本不兼容，或者重新加载后仍找不到“历史诊断”，先卸载默认版，再安装兼容布局版。兼容布局版解决的是安装清单和面板位置兼容，入口可能在左侧；扩展自身功能相同，但编辑器实际能提供多少代码能力，必须看“编辑器兼容性”的自动检测，不能仅凭安装成功或面板位置判断。

### “找不到 CSV”

检查字典里的 `data_source`。文件名、大小写和 `.csv` 后缀都必须与真实文件一致。

### “找不到列”

打开真实 CSV，看第一行表头。字典里的 `data_field` 必须与它完全一致，不能自己改成更好看的名字。

### “定义路径不存在”

字典中的 `definition_path` 是相对代码仓根目录的路径。不要写某台电脑的 `C:\...` 或 `E:\...` 绝对路径。

### “网页没有调用连线”

确认光标在有调用行为的函数内，再点击兼容性报告里的“调用关系”查看实际检测结果。如果语言服务还在索引，稍后点“重新检测”；如果报告明确说当前编辑器没有提供调用关系，网页会如实显示“没有拿到证据”，不会把它说成“代码里绝对没有调用”。有些函数确实没有可确认的直接调用，这时只显示一个节点也是正常的。

## 九、OpenCode 怎么用

普通用户不使用 OpenCode 也不影响编辑器内的历史诊断功能。需要 AI 查询时，再看 [OpenCode 使用说明](OpenCode-网页工作台.md)。
